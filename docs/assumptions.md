# Допущения прототипа

Правила, которые в постановке ещё не согласованы. Для интерактивного демо выбраны конкретные значения;
это **не окончательные продуктовые решения**. Числовые значения собраны в `src/domain/assumptions.ts`
и меняются в одном месте.

| Вопрос | Допущение в прототипе | Где в коде |
|---|---|---|
| Способ входа | Почта указывается при покупке; сразу после оплаты новый покупатель попадает в кабинет и создаёт пароль. Дальше вход — почта + пароль. Почта не подтверждается, письма не отправляются, восстановления пароля нет. Пароль хранится демо-хешем (не безопасно). | `operations.ts: completePurchase, setPassword, login` |
| Покупка на почту, у которой уже есть кабинет | Аккаунт закрепляется за этим пользователем, но в кабинет пускает только вход по паролю. | `completePurchase` |
| Количество подписок | Одна подписка на клиента; вторая покупка на ту же почту запрещена, предлагается продление. | `startPurchase` |
| Длина «месяца» | 30 суток с момента оплаты. | `ASSUMPTIONS.periodDays` |
| «Скоро закончится» | За 5 дней до окончания. | `ASSUMPTIONS.expiringSoonDays` |
| Продление досрочно | Новые 30 дней добавляются к текущей дате окончания. | `nextPaidUntil` |
| Продление после окончания | Новые 30 дней отсчитываются от момента оплаты. | `nextPaidUntil` |
| Цена при продлении | Текущая цена тарифа на момент перехода к оплате. | `startRenewal` |
| Сохранение аккаунта после окончания | 14 дней. | `ASSUMPTIONS.graceDays` |
| Работа в период сохранения | Приостановлена: доступы скрыты, продление доступно. | `ASSUMPTIONS.workDuringGrace` |
| После периода сохранения | Аккаунт автоматически в продажу **не** возвращается и остаётся закреплённым; продление по-прежнему доступно. Решение о возврате — за командой. | `ASSUMPTIONS.autoReleaseAfterGrace` |
| Цена в уже открытой оплате | Сумма фиксируется при переходе к оплате; изменение цены админом её не меняет. Новая покупка — по новой цене. | `startPurchase` |
| Резервирование аккаунта | При переходе к оплате аккаунт не резервируется. Свободный аккаунт выбирается в момент успешной оплаты; если его успели купить, платёж не проходит («деньги не списаны»), наличие не уходит в минус. | `completePurchase` |
| Повторное подтверждение платежа | Идемпотентно: завершённый платёж не меняется. | `completePayment` |
| Блокировка | При блокировке доступы скрыты, продление недоступно, пока нет решения. Клиент сам сообщает о блокировке. | `requestReview`, `describeSubscription` |
| Замена | Берётся свободный аккаунт того же тарифа из наличия (наличие уменьшается); срок подписки не меняется; старый аккаунт остаётся заблокированным и не продаётся. Если свободных нет — замена в демо невозможна. | `resolveReview` |
| Решение по блокировке | Выбирается в демо-панели с вымышленным текстом. В админку модуль замен не добавлялся. | `demoControls.setIncident` |
| Отказ в замене | Аккаунт остаётся заблокированным, продление недоступно. Возвраты и компенсации не описаны. | `resolveReview` |
| Статус заявки | Админ может отметить «связались» — внутренняя отметка, человеку ничего не отправляется. | `setRequestStatus` |
| Корпоративные заявки при скрытом блоке | Не принимаются. | `submitCorporate` |
| Тарифы и цены | «Старт» 2 900 ₽, «Рабочий» 5 900 ₽, «Интенсив» 11 900 ₽; лимиты описаны словами без цифр. Условные значения. | `seed.ts` |
| UnoWork и BB | Описания и шаги подключения — общие формулировки; точные шаги нужно сверить с реальными продуктами. | `AccessTabs.tsx` |

## Открытые продуктовые вопросы

- Окончательный способ входа и подтверждение почты.
- Длительность хранения аккаунта после окончания, можно ли в это время работать и когда аккаунт возвращается в продажу.
- Правило расчёта срока при досрочной оплате и после окончания.
- Условия для других причин недоступности аккаунта (не блокировка).
- Сроки рассмотрения блокировки, возвраты, компенсация времени.
- Реальные лимиты тарифов и цены.
- Может ли один клиент иметь несколько подписок.
- Как поступать, если для замены нет свободного аккаунта.
